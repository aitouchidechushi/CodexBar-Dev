# 第一阶段并发检测实施记录

当前状态：0.48.2 / build 92，用户于 2026-09-22 确认验收通过，按此前约定更新 GitHub；保留全部已验收代码，不在发布前混入新的功能修改。

1. Rust 独立检测模块：Kimi、MiniMax、GLM 的固定官方端点；默认模型为 kimi-for-coding、MiniMax-M2.5、glm-4.7；SSE 有界解析；两请求、无自动重试；分类与重叠测试先行。
2. 桌面任务协调器：一个全局任务，枚举启用供应商的启用 Key，串行执行；逐项复核凭据，跨窗口共享进度，取消在途任务；敏感内容不进结果。
3. 统一入口与卡片状态：用户明确要求点击直接检测，不再二次确认；主窗口按钮在“刷新全部”左侧，按钮悬停说明可能收费。保留进度和取消。各供应商失败计数旁悬停查看本供应商结果，正常 Key 无标签，受限单独标记。证据仅保存在进程内，重启后需重新检测。
4. 验证：分类与流解析单元测试、HTTP 模拟双流测试、任务枚举/结果失效测试、界面交互测试、全部前端与 Rust 回归、构建与版本一致性。
5. 验收与发布：0.48.2 原验收 EXE 作为 Release 附件；源码与可执行文件分别交付。不覆盖旧程序、不强制结束现有进程；不同版本启动前先由用户退出旧进程。具体文件与哈希见 PUBLICATION.md。

重要边界：本地观察到双流重叠不等于测得服务端真实并发上限；无重叠为不确定。普通 429/403 不直接标受限。第一阶段不调用 Codex/GPT。官方端点之外的自定义代理不自动转发凭据。每条请求限制最多 512 输出 token、30 秒；可能收费，取消不保证服务端立即停止计费。不存在自动后台模型探测。
