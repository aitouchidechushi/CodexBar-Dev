# 0.48.0 并发检测验收说明

历史候选版记录，非当前操作说明。0.48.2 已改为点击直接检测、各供应商悬停查看结果，并已通过用户验收；当前下载与使用说明见 [PUBLICATION.md](../PUBLICATION.md)。下文保留当时验证范围。

这是本地候选版本，尚未发布到 GitHub。版本号 0.48.0，构建号 90。

## 如何验收

1. 通过旧版菜单的“退出”完全关闭旧版；只关闭窗口可能仍驻留托盘。不要同时运行两个不同路径的版本。
2. 启动 `output/acceptance-0.48.0-concurrency/CodexBar-0.48.0-portable.exe`，检查已有账号、Key 标签及额度是否保留。
3. 主面板点击唯一的“检测并发”。此时只显示确认列表，不发送模型请求。核对启用的 Kimi、MiniMax、GLM 及其全部启用 Key；Codex/GPT 等暂未适配项会明确跳过。
4. 核对模型和官方端点，暂停其他软件同账号任务。确认开始后才发送可能消耗套餐或余额的模型请求。Key 间串行，每个 Key 最多两条请求，每条 30 秒超时、最多 512 输出 Token，无自动重试。
5. 检测期间观察进度并可取消。取消是停止本地请求，不保证服务端即时停止处理或计费。
6. 明确并发拒绝时，对应 Key 卡片显示“并发受限”。普通限流、额度不足、权限或网络错误不会被当成并发限制。正常卡片不额外显示正常标签。
7. 在结果详情查看每个 Key 的状态。结果不确定时，既有受限标签保留并说明是上次结果；双请求响应重叠后清除。更换 Key、端点或检测模型后不复用旧证据。证据只保留在本次运行中。

## 已完成的离线验证

- 前端 351 项测试通过，包括批量确认、无自动调用、标签显示及失败处理。
- Rust 核心 941 项、命令入口 1 项、桌面 553 项测试通过。
- 7 处版本来源一致；前端类型检查及生产资源构建通过。
- 审查修订后的 Windows Release EXE 编译成功，保留原版文件，没有替换原运行程序。
- 使用本地模拟 HTTP 服务验证两路流式响应及供应商错误分类，没有使用真实 Key 发起付费模型测试。
- 独立代码审查发现的确认后换 Key、网络库默认重试、结果过度表述问题已处理。

## 不能据此推断的事项

响应重叠是客户端观察，不是服务端精确并发上限。其他程序占用同账号、服务端排队和网络缓冲都可能影响结果。本次未实测真实供应商兼容性，模型或套餐拒绝调用时不会伪装官方客户端绕过限制。

先前完整测试曾出现 PTY 测试间歇失败；此次完整测试通过不等于该历史问题已经根治。安装、升级、卸载生命周期等既有待验收项不属于本功能的完成声明。
